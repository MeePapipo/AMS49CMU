## โครงข้อมูลหนึ่งรายการ

คีย์ `localStorage` คือ `ams49.proto.v5` — **ถ้าแก้โครงนี้ต้องขึ้นเลขเวอร์ชัน**
ไม่งั้นเครื่องที่เคยเปิดต้นแบบเดิมจะอ่านของเก่าที่โครงไม่ตรงมาแสดงผิด

ที่ขึ้นจาก v4 เป็น v5 ทั้งที่ชื่อฟิลด์แทบไม่เปลี่ยน เพราะ **ความหมายของข้อมูลเดิมเปลี่ยน** —
ไซส์ `XXL` เปลี่ยนรหัสเป็น `2XL` (แถวเก่าจะหาราคาไม่เจอแล้วตกไปคิด 500) และไซส์พิเศษถูกยกเลิก
(แถวเก่าจะโชว์คำว่า `SPECIAL` ดิบ ๆ) ทั้งสองอย่างพังแบบเงียบ ๆ ถ้าไม่บังคับ re-seed

```
ref donation shirtQty sizes[]                    ← ของที่สั่ง
transferAt submittedAt verifiedAt status note    ← สถานะ
name studentId phone email lineId                ← ผู้บริจาค
recipient recipientPhone
addrLine province zip shipNote address           ← จัดส่ง
slip
```

- `sizes` เก็บเป็น **array แบน** `['M','M','L']` ไม่ใช่ `{M:2,L:1}` — ฟอร์มคิดเป็น counts
  แล้วแปลงด้วย `countsToSizes()` / `sizesToCounts()` ก่อนลง store
- ไม่มีฟิลด์ `amount` — ยอดรวมคำนวณจาก `donation + ราคาเสื้อรายตัว` ผ่าน `money()` เสมอ
  เก็บซ้ำเมื่อไรจะมีวันที่สองค่าไม่ตรงกัน
- **ห้ามคิดค่าเสื้อเป็น `qty × 500`** — ตั้งแต่ v5 ราคาต่อตัวไม่เท่ากันแล้ว (2XL ขึ้นไปมีส่วนเพิ่ม)
  ต้องบวกรายตัวผ่าน `priceForSize()` เท่านั้น · `money().surcharge` คือส่วนเพิ่มรวมของรายการ
  มีไว้อธิบายให้ผู้ใช้และแอดมินเห็นว่าทำไมยอดไม่ลงท้ายด้วย 00
- `address` เป็นสตริงประกอบไว้แสดงผล ส่วน `addrLine/province/zip` เก็บแยกเพราะแอดมินต้อง
  พิมพ์ใบปะหน้าพัสดุและ export CSV · `shipNote` (“โทรก่อนส่ง”) **ไม่รวม**อยู่ใน `address`
  เพราะเป็นคำสั่งถึงคนส่ง ไม่ใช่ส่วนหนึ่งของที่อยู่

### ตัวเลขที่ต้องรู้ใน `app.js`

| ค่า | ความหมาย |
|---|---|
| `SHIRT_PRICE = 500` | ราคา**ฐาน**ต่อตัว (ไซส์ SS–XL) รวมค่าจัดส่งแล้ว |
| `SIZES[].extra` | ส่วนเพิ่มรายไซส์ — SS–XL = 0 · **2XL +20 · 3XL +30 · 4XL +40 · 5XL +50**<br>ถ้าราคาเปลี่ยน แก้ที่ตารางนี้ที่เดียว ทั้งระบบคิดผ่าน `priceForSize()` |
| `SIZE_MAX = 99` | เพดาน**ต่อหนึ่งไซส์** — เป็นตัวกันพิมพ์พลาด ไม่ใช่โควตา |
| `BULK_HINT = 10` | เกินนี้แค่ขึ้นข้อความให้กรรมการโทรยืนยัน ยังกดต่อได้ตามปกติ |
| `SIZE_TOLERANCE_IN = 1` | ขนาดจริงคลาดเคลื่อนจากตารางได้ ±1 นิ้ว ถือว่าปกติของงานตัดเย็บ |

ไซส์มี SS S M L XL 2XL 3XL 4XL 5XL — **ไม่มีไซส์พิเศษสั่งตัดแล้ว** (ยกเลิกใน v5)

**ภาพ `size-chart.jpg` เป็นตารางต้นฉบับจากผู้ผลิตซึ่งมีถึง 3XL เท่านั้น** 4XL/5XL เพิ่มมาทีหลัง
จึงไม่อยู่ในภาพ — ตารางเลือกจำนวนบนหน้าเว็บวาดจาก `SIZES` จึงครบกว่าและเป็นฉบับที่ต้องยึด
ถ้าวันหนึ่งได้ภาพตารางใหม่จากผู้ผลิต ให้เปลี่ยนภาพแล้วลบย่อหน้ากำกับใต้ภาพใน `support.html` ออก

## แคชของเบราว์เซอร์ — เรื่องที่เคยทำให้ยอดเงินผิดมาแล้ว

ทุกหน้าเรียก assets ด้วย `?v=N` (`assets/app.js?v=6`, `assets/system.css?v=6`)
และ `app.js` ประกาศ `ASSET_VERSION` ตัวเดียวกันไว้ **ทั้งสองที่ต้องตรงกันเสมอ**

**แก้ `app.js` หรือ `system.css` เมื่อไร ต้องขึ้นเลขนี้ทั้งสองที่**

เพราะเคยเกิดขึ้นจริง: เบราว์เซอร์แคช `app.js` ตัวเก่าไว้ แล้วโหลด HTML ตัวใหม่
HTML ใหม่เรียกฟังก์ชันที่ JS เก่ายังไม่มี → `order()` โยน error ทุกครั้งที่ถูกเรียก →
**ยอดรวมค้างไม่ขยับ แต่ช่องจำนวนยังกดเพิ่มได้ตามปกติ** ผู้ใช้จึงไม่รู้ตัวเลยว่ายอดผิด
ซึ่งบนหน้าที่คนกำลังจะโอนเงินคืออาการที่แย่ที่สุดเท่าที่เป็นไปได้

`support.html` จึงมีด่านสุดท้ายเพิ่ม — ถ้า `A.ASSET_VERSION` ไม่ตรงกับที่หน้านั้นคาดไว้
จะขึ้นแถบแดงบอกให้กด Ctrl+Shift+R แล้ว**หยุดทั้งหน้า** ไม่ยอมแสดงยอดใด ๆ

### กับดักที่เสียเวลาไปแล้วครั้งหนึ่ง — อย่าเขียน `1fr` เฉย ๆ

`grid-template-columns: 1fr` มีขั้นต่ำเป็น **min-content** ของสิ่งที่อยู่ข้างใน
และ `overflow-wrap: break-word` (ที่ตั้งไว้บน `body`) **ไม่ได้ลด min-content** ให้
ข้อความไทยยาว ๆ ไม่มีช่องว่างจึงมี min-content เท่ากับความยาวทั้งประโยค แทร็กเลยโป่งจนทั้งหน้าเลื่อนแนวนอน

→ ทุก grid ที่มีข้อความไทยหรือตารางอยู่ข้างใน **ต้องใช้ `minmax(0,1fr)`** รวมถึงใน media query
ที่เขียนทับด้วย (`.wiz-grid`, `.ledger-grid`, `.hero-grid`, `.ledger-cards tbody tr`)

### สองคลาสที่ต้องรู้ก่อนแก้ตาราง

- `.ledger-cards` — เลือกใช้เอง ตารางไหนติดคลาสนี้จะพลิกเป็นการ์ดบนจอแคบ
- `.ledger-admin` — เลย์เอาต์การ์ดของหลังบ้านโดยเฉพาะ อาศัย `data-l="…"` บนแต่ละ `<td>`
  เป็น label เวลาซ่อน `<thead>` **ถ้าเพิ่มคอลัมน์ใหม่ต้องใส่ `data-l` และวาง grid-row ใน CSS ด้วย**

## ยังไม่มี ต้องเพิ่มก่อนใช้จริง

- **ระบบล็อกอินแอดมินของจริง** — ตอนนี้ `admin` / `Admin001` เป็น **ประตูหลอก** ไม่ใช่การยืนยันตัวตน
  ชื่อผู้ใช้กับรหัสผ่านฝังอยู่ใน `admin.html` ที่ใครก็โหลดไปอ่านได้ (กด Ctrl+U ก็เห็น)
  เปลี่ยนเป็นรหัสยาวขึ้นหรือเข้ารหัสไว้ก็ไม่ช่วย เพราะการตรวจเกิดที่เครื่องผู้ใช้ ไม่ใช่ที่เซิร์ฟเวอร์
  หน้านี้เห็นชื่อ เบอร์ ที่อยู่ และสลิปของทุกคน — **ห้ามขึ้นเว็บจริงโดยพึ่งด่านนี้**
  ทางแก้ที่แนะนำคือ **Cloudflare Access** (ฟรีถึง 50 users) ล็อกที่ระดับเซิร์ฟเวอร์ก่อนถึงไฟล์
  และอย่าลืมลบบรรทัดที่โชว์รหัสใต้ปุ่มเข้าระบบทิ้งด้วย

- นโยบายลบข้อมูลส่วนบุคคลหลังปิดโครงการ (PDPA) — ในฟอร์มเขียนสัญญาไว้แล้วว่าจะลบ ต้องมีคนทำจริง

## ข้อตัดสินใจที่ห้ามเปลี่ยนโดยไม่ตั้งใจ

1. **ค้นสถานะด้วยรหัสอ้างอิงเท่านั้น ห้ามใส่ช่องค้นด้วยชื่อ** — รุ่นเดียวคนไม่เยอะ
   ค้นด้วยชื่อเมื่อไรจะเดาออกทันทีว่าใครบริจาคเท่าไร
2. **`status.html` ไม่โชว์ที่อยู่เต็ม** โชว์แค่จังหวัด+ไปรษณีย์ — หน้านั้นเปิดได้ด้วยรหัสอ้างอิงอย่างเดียว
   ถ้ารหัสหลุด อย่างน้อยที่อยู่บ้านต้องไม่หลุดตาม
3. **ไม่เอาภาพถ่ายสมุดบัญชีขึ้นเว็บ** — ไฟล์ต้นฉบับมีลายเซ็นผู้มีอำนาจและตราประทับธนาคาร
   ใช้เป็นข้อความ + ปุ่มคัดลอกแทน
4. **ไม่มี QR พร้อมเพย์ และจะไม่มี** — บัญชีนี้เป็นบัญชีร่วมสองชื่อ ซึ่งผูกพร้อมเพย์ไม่ได้
   ทางแก้คือปุ่ม “คัดลอกยอด” ให้วางในแอปธนาคารแทนการพิมพ์
5. **ยอดที่แจ้ง = ยอดที่ระบบคำนวณ** ผู้ใช้พิมพ์ยอดเองไม่ได้ — โอนผิดยอดให้แอดมินตีกลับ
   ดีกว่าปล่อยให้กรอกเลขที่ไม่ตรงกับของที่สั่ง
6. **ไม่จำกัดจำนวนเสื้อ** — `SIZE_MAX`/`BULK_HINT` เป็นตัวกันพิมพ์พลาดและตัวเตือน ไม่ใช่โควตา
7. หน้าสาธารณะแสดงได้แค่ เวลา · รหัสอ้างอิง · สถานะ · ยอด — ชื่อ เบอร์ ที่อยู่ สลิป
   อยู่หลัง `admin.html` เท่านั้น

## ทำเป็นของจริงต่อ

Stack ฟรีที่แนะนำ: **Cloudflare Pages + D1 + R2 + Access** — ไม่ต้องผูกบัตร ไม่มี sleep
(Supabase free tier จะ pause โปรเจกต์เมื่อไม่มี traffic 7 วัน ซึ่งเสี่ยงกับงานที่ยาวถึงปลายปี 2569)

`assets/system.css` ย้ายไปใช้กับของจริงได้เลยทั้งไฟล์ ส่วนที่ต้องเขียนใหม่คือครึ่งบนของ `assets/app.js`
ซึ่งตอนนี้อ่าน/เขียน `localStorage` — เปลี่ยนเป็นเรียก API แทน โดยคง interface เดิม
(`Store.all / add / find / update / stats`) ส่วนครึ่งล่าง (ตัวนับไซส์ formatter badge clipboard)
ใช้ต่อได้ทั้งหมด
